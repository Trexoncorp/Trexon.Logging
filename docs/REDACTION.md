# Маскирование по регулярным выражениям

[Русский](REDACTION.md) · [English](en/REDACTION.md) · [Deutsch](de/REDACTION.md)

[Оглавление](README.md) · [Назад](OUTPUT.md) · [Далее](ERRORS_AND_LIFETIME.md)

`Redact` преобразует данные события до глобальных фильтров и dispatch.
Все получатели, включая пользовательский `ILogSink`, видят обработанный
`LogEvent`. Правило задаётся приложением; библиотека не определяет секреты
автоматически.

## Пример

<!-- verify: redaction -->
```csharp
using System.Text.RegularExpressions;
using Trexon.Logging;

using var logger = Logger.Create(config => config
    .Redact(@"Bearer\s+[^\s""}]+", "Bearer ***", RegexOptions.IgnoreCase)
    .Redact(@"token=[A-Za-z0-9_-]+", "token=***")
    .WriteTo.Console(console => console.Timestamp(null))
    .WriteTo.File("logs/redacted.jsonl", file => file.Json()));

logger.Info("Authorization: {Authorization}", "Bearer demo-secret");
logger.Info("Payload {Payload}", new { Token = "token=abc123", Tags = new[] { "safe" } });
logger.Error(new InvalidOperationException("token=error123"), "Import failed");
```

Регулярка — часть политики конкретного приложения. Пример для Bearer ограничен
перечисленными разделителями; другие форматы токенов требуют своего шаблона.

## Контракт Redact

```csharp
LoggerConfiguration Redact(
    string pattern,
    string replacement = "***",
    RegexOptions options = RegexOptions.None,
    TimeSpan? timeout = null);
```

`null` в timeout выбирает 100 мс. Указанный timeout должен быть конечным и
положительным; дополнительные ограничения проверяет конструктор `Regex`.
Ошибки pattern/options/timeout возникают при настройке, до создания логгера.
В replacement действуют стандартные подстановки Regex.Replace, например `$1`.

Несколько правил выполняются в порядке регистрации; последующее видит
результат предыдущего. Для совпадений без учёта регистра передайте
`RegexOptions.IgnoreCase`.

## Какие данные изменяются

| Область | Обработка |
| --- | --- |
| `MessageTemplate` | Все зарегистрированные правила |
| `Message` | Рендеринг из обработанных свойств, затем правила для готового текста |
| String-значение в `Properties` | Все правила |
| Строки внутри JSON-массива/объекта | Рекурсивное применение правил |
| `ExceptionInfo.Type`, Message, StackTrace | Правила для строк, включая children |
| `CallerInfo.MemberName`, FilePath | Правила для строк |
| Числовые и прочие сохранённые простые типы | Типизированное значение сохраняется |
| Имена ключей `Properties`/вложенного JSON | Сохраняются |
| Timestamp, level, номер строки caller | Сохраняются |

В частности, значение Guid/DateTime/TimeSpan не превращается в строку ради
маскирования свойства. Regex может изменить его текстовое представление внутри
`Message`, но в `Properties` останется исходное типизированное значение.
Если значение нужно маскировать как текст, передайте его строкой.

При маскировании вложенные строки обрабатываются до JSON-экранирования. Поэтому
совпадение с реальным newline может быть скрыто и в сложном свойстве, и в его
текстовом представлении. Затем правила применяются к целому сообщению — это
также покрывает совпадение на границе литерала шаблона и аргумента.

Из-за этих двух стадий replacement должен быть устойчив к повторному применению
правила. Простой вариант — `***`. Шаблон, который совпадает с собственным
replacement, может повторно изменить значение в итоговом сообщении.

## Timeout и ошибки

Timeout ограничивает отдельную regex-операцию, а не суммарную длительность
всех правил и всех свойств события. Большой объект с множеством строк требует
много операций; маскирование выполняется в потоке, который пишет лог.

Если regex-операция истекла по времени или другая стадия обработки дала ошибку:

1. событие не передаётся ни одному sink;
2. в `OnError` приходит `LoggingFailure` со стадией `Pipeline`;
3. следующий вызов логирования может продолжить работу.

Шаблон не заменяется незамаскированной fallback-записью.

## Диагностика и границы

`LoggingFailure.Exception` — исходная техническая ошибка pipeline/sink.
Она не является `ExceptionInfo` прикладного события и не проходит через эти
правила. Для собственной диагностики можно выводить `failure.Stage` и тип
исключения, а состав подробностей выбирать отдельно.

Фильтры получают данные после маскирования: сравнение с исходным токеном может
перестать выполняться. Имена свойств используйте как постоянную схему события,
а значения передавайте отдельными аргументами. Проверьте правила на реальных
формах своих данных и включите `OnError`, чтобы видеть отбрасывание событий.

## Пример сразу завершается или выводит исключение

Консольный пример выполняет несколько записей и завершается; постоянно
работающего сервиса или интерфейса у него нет. Строка «Пример завершён»
и путь к JSON-файлу означают, что выполнение дошло до конца.

При запуске с `--demo-error` исключение создаётся специально, перехватывается
и передаётся в `logger.Error`. Stack trace в этом случае показывает содержимое
лога. Обычный запуск без этого аргумента не включает демонстрацию исключения.
Команды приведены в [быстром старте](GETTING_STARTED.md#вариант-1-запустить-готовый-пример).

## Сообщение не появилось

| Проверка | Что посмотреть |
| --- | --- |
| Общий порог | Debug/Trace по умолчанию отключены; задайте общий MinimumLevel |
| Порог sink | Событие должно пройти оба порога |
| `None` | Logger или конкретный sink могли быть отключены |
| Выбранный поток | По умолчанию Console.Error, а не Console.Out |
| Глобальный/локальный Filter | Предикат мог вернуть false |
| Pipeline failure | Подключите OnError; возможен regex timeout или ошибка снимка/формата |
| Ошибка конкретного sink | OnError содержит тип sink и исходное исключение |
| Повторный вход | Запись из собственного callback пропускается |
| Настройка только файла | Добавление File не оставляет скрытый Console sink |

Результат `true` у `logger.IsEnabled(LogLevel.Debug)` не является обещанием
доставки: метод проверяет пороги/состояние, но не выполняет пользовательские
предикаты.

## Закрытый logger или старое view

`ObjectDisposedException` после using/Shutdown — часть контракта. Убедитесь,
что root живёт дольше всех его пользователей и что Log.Configure не заменил
root сохранённого ранее Log.Bind-представления. Закрытие view не закрывает root,
а закрытие root инвалидирует все views.

## Не видно RequestId в текстовой строке

Контекст хранится в Properties. Стандартный текстовый sink не выводит весь
словарь автоматически. Используйте placeholder `{RequestId}` в сообщении,
Json() или собственный sink. Проверьте также приоритет Bind и аргументов
шаблона относительно scope и то, что scope активен в нужном async flow.

## Scope не снимается или снят слишком рано

Используйте using и обратный порядок закрытия. При out-of-order Dispose
возникает InvalidOperationException без удаления текущего контекста. Дочерний
ExecutionContext наследует scope; последующее снятие в дочернем потоке само
по себе не меняет родительский контекст. [Подробности](CONTEXT.md).

## Цветов нет или видны управляющие коды

Auto проверяет стандартный writer и отсутствие перенаправления. Для своего
writer используйте Always, если принимающая сторона понимает ANSI, либо Never
для plain text. JSON не окрашивается. Выбранный Console.Error сохраняется
при регистрации sink: перенаправляйте его до Logger.Create либо передайте Writer.

## Время отличается от локального

Текстовая зона по умолчанию UTC. Передайте `TimeZone(TimeZoneInfo.Local)` или
явный TimeZoneInfo. Json() использует timestamp события, а не текстовую зону.
Формат `HH:mm:ss` не содержит offset; добавьте `zzz`, если зона важна при чтении.

## Caller указывает внешний frame, нет файла или строки

WithCaller должен быть включён глобально, Caller(false) не должен скрывать его
в выбранном sink. Поиск использует StackTrace, а не caller-атрибуты компилятора.
Inlining, оптимизация, async state machine и доступность PDB влияют на результат.
Если source path отсутствует, JSON filePath опускается, lineNumber может быть 0.
Полный path в JSON может содержать нормализованный build-путь вроде `/_/`.

## Нет stack trace исключения

Передайте Exception через специальную перегрузку, проверьте ExceptionDetails.
У объекта `new Exception(...)`, который ещё не выбрасывали, stack trace обычно
отсутствует. Logger не генерирует стек броска за исходное исключение.
У AggregateException Message может уже включать сообщения children даже при
ExceptionDetails(false).

## Placeholder остался в тексте или массив распался на аргументы

Поддерживаются `{Name}` и `{Name:format}`. Числовые placeholders, `@`, `$`,
alignment и вложенные скобки в грамматику не входят. Пропущенное значение также
оставляет placeholder, если соответствующего контекстного свойства нет.
Для массива как одного значения используйте `(object)array`.
[Правила связывания](MESSAGES.md).

## JSON содержит обратные слэши и Unicode escapes

Новые записи выводят кириллицу и другие алфавиты читаемыми символами.
Старые строки в файле не переписываются: повторный запуск дописывает лог.
Кавычки, обратные слэши и управляющие символы по-прежнему экранируются;
некоторые символы, например emoji, также могут быть экранированы.
JSON-парсер восстановит исходные строки. `message` сложного объекта может сам содержать
JSON-представление объекта как строку; для машинной обработки читайте
исходную структуру в `properties`, а не разбирайте текст message повторно.

## Событие с объектом пропало, возник Pipeline

Возможны цикл в объекте, неподдерживаемый сериализатором тип, бросающий getter,
неправильный формат простого значения, ошибка предиката или regex timeout.
Свойства аргументов фиксируются до dispatch, поэтому событие отбрасывается
целиком. Передавайте небольшой DTO с необходимыми данными и смотрите OnError.
NaN/Infinity могут отдельно привести к ошибке JSON sink при сериализации;
простой текстовый sink при этом способен продолжить работу.

## Файл появился в другом месте или не открылся

Относительный путь привязывается к рабочей папке при настройке File. Если нужен
каталог приложения, постройте путь через AppContext.BaseDirectory. Открытие
происходит при Logger.Create, поэтому ошибка доступа/пути возникает сразу.
Один файл не предназначен для одновременного использования разными writers.

Повторный Log.Configure с тем же файлом может сначала пытаться открыть новый
writer, пока старый ещё не закрыт. Настраивайте процессный logger при запуске
или явно завершайте предыдущий в согласованный момент.

## Регулярка маскирует не всё

Правило применяется к строкам, а типизированные числа, Guid, даты и ключи
свойств сохраняются. Проверьте форму исходных данных, RegexOptions и replacement.
У вложенного объекта строки проходят обработку до JSON-экранирования, а готовое
сообщение — ещё одну стадию. Replacement должен быть устойчивым, например `***`.
Технический LoggingFailure.Exception не является маскированным ExceptionInfo.
[Границы маскирования](REDACTION.md).

## Flush ничего не меняет

У встроенного file writer включён AutoFlush: его буфер уже сбрасывается после
записи. Flush полезен для выводов с накоплением данных и оставляет логгер открытым.
Dispose дополнительно закрывает принадлежащие логгеру ресурсы. Это не гарантия
физической записи на диск при аварии. [Подробности](ERRORS_AND_LIFETIME.md#flush-и-dispose).

## Сборка или запуск тестов не работают

| Симптом | Действие |
| --- | --- |
| SDK не поддерживает target / slnx | Используйте SDK 10 из global.json |
| Для net8.0 не найден framework | Установите runtime .NET 8 |
| Runner не понимает старую команду | Используйте `dotnet test --solution Trexon.Logging.slnx` |
| После смены runner ноль тестов | Restore и build заново, затем test --no-build |
| Локальный пакет старый | Новая уникальная prerelease-версия либо отдельный package cache |
| Ошибка GitHub publish | Проверьте NUGET_USER, policy, environment и формат тега |

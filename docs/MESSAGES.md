## Шаблон и значения

Шаблон содержит имена, аргументы передаются отдельно. Благодаря этому событие
сохраняет шаблон, готовое сообщение и свойства с их типами:

<!-- verify: message-templates -->
```csharp
using Trexon.Logging;

using var logger = Logger.Create(config => config
    .WriteTo.Console(console => console.Timestamp(null)));

logger.Info("Order {Id}: {Price:0.00}; repeat {Id}", 42, 12.5m);
logger.Info("Literal {{Id}}, actual {Id}", 42);
logger.Info("Nullable {Value}", (object?)null);
logger.Info("Missing {Value}");
logger.Info("Customer {Customer}", new { Name = "Anton", Orders = 3 });
```

Первые четыре строки:

```text
[INF] Order 42: 12.50; repeat 42
[INF] Literal {Id}, actual 42
[INF] Nullable null
[INF] Missing {Value}
```

Для первой записи в `Properties` будут `Id = 42` и `Price = 12.5m`.
`MessageTemplate` останется `Order {Id}: {Price:0.00}; repeat {Id}`; при
включённом маскировании к нему также применяются правила.

Интерполированная строка `$"Order {id}"` уже отформатирована вызывающим кодом.
Логгер принимает её как обычный текст и не восстанавливает свойство `Id`.

## Поддерживаемый синтаксис

| Форма | Поведение |
| --- | --- |
| `{Name}` | Именованное свойство |
| `{Price:0.00}` | Формат через `IFormattable` с invariant culture |
| `{{` / `}}` | Литерал `{` / `}` |
| Повтор `{Name}` | Повторно использует то же свойство |
| Имя без аргумента | Использует контекстное свойство либо остаётся в тексте |
| `{0}`, `{@Object}`, `{$Object}`, `{Name,10}` | Не входят в грамматику MVP; остаются литералами |

Имя соответствует `[A-Za-z_][A-Za-z0-9_]*`. Регистр значим: `Id` и `id`
различаются. Имя связывается со следующим аргументом при первом появлении.
Текстовые комментарии в примерах описывают простой синтаксис; вложенные
фигурные скобки внутри placeholder не являются поддерживаемой конструкцией.

Двойные фигурные скобки обрабатываются до распознавания placeholders. Полный
парсер расположен в [MessageTemplate.cs](../Trexon.Logging/Internal/MessageTemplate.cs).

## Недостающие и лишние аргументы

Если аргумента нет, рендерер ищет одноимённое значение в объединённом контексте.
Отсутствующее значение сохраняет исходный placeholder. Это позволяет писать
шаблон `"Request {RequestId}"` при активном scope с `RequestId`.

Лишние аргументы сохраняются в свойствах `_argN`, где N — исходный индекс
аргумента, начиная с нуля. Например, `Info("{Value}", 10, 20)` создаёт
`Value = 10` и `_arg1 = 20`. При конфликте с именем из шаблона к служебному
имени добавляется `_`, пока оно не станет свободным.

Для явного `null` удобно передавать `(object?)null`. Если на уровне вызова
попал null-массив `params`, реализация трактует его как один null-аргумент;
nullable-аннотация самого массива в текущей сигнатуре остаётся non-null.

## Массив как одно значение

Из-за `params object?[]` массив ссылочных типов может стать самим набором
аргументов. Приведите его к `object`, если нужен один структурированный массив:

<!-- verify: array-property -->
```csharp
using Trexon.Logging;

using var logger = Logger.Create(config => config
    .WriteTo.Console(console => console.Json()));
string[] tags = ["new", "paid"];
logger.Info("Tags {Tags}", (object)tags);
```

Свойство `Tags` в JSON будет массивом из двух элементов.

## Форматы

Формат действует на значение, реализующее `IFormattable`, например decimal,
DateTime, DateTimeOffset или Guid. Культура фиксирована: `12.5m` с `0.00`
даёт `12.50` независимо от культуры процесса. Формат даты здесь относится
к свойству сообщения; дата самого события настраивается через `Timestamp`.

Сложные объекты превращаются в `JsonElement`, поэтому специальный числовой
или пользовательский формат к такому снимку не применяется. Недопустимый
формат простого значения может вызвать ошибку стадии `Pipeline`: событие
не записывается, причина передаётся в `OnError`.

## Как фиксируются значения

| Входное значение | Что хранится в `Properties` |
| --- | --- |
| `null`, string, bool, встроенные числовые типы | Исходное простое значение |
| DateTime, DateTimeOffset, Guid, TimeSpan | Соответствующее значение типа |
| char | Строка из одного символа |
| enum | Результат `ToString()` |
| JsonElement | Независимый клон |
| DTO, коллекция, словарь, прочий объект | JSON-снимок через System.Text.Json |

Шаблонные аргументы фиксируются во время записи. Глобальные свойства — при
создании ядра, `Bind` — при создании view, scope — при `PushScope`.
Последующее изменение коллекции не меняет ранее сохранённый снимок.

Пользовательский sink может разобрать сложное значение через `JsonElement`:

```csharp
if (logEvent.Properties["Customer"] is System.Text.Json.JsonElement customer)
{
    string? name = customer.GetProperty("Name").GetString();
}
```

Это фрагмент `Emit(LogEvent logEvent)` собственного sink.
Свойства объекта сериализуются стандартными правилами System.Text.Json;
отдельных настроек сериализатора, destructuring-политик и конвертеров в MVP нет.
Циклы, неподдерживаемые типы и исключения getter могут сорвать создание снимка.
Для аргумента записи это ошибка `Pipeline`; для `Bind`, scope и создания
логгера исключение возникает непосредственно в соответствующем вызове.

JSON-вывод может отдельно отклонить значения, которые нельзя представить его
стандартным сериализатором, например `double.NaN`: сработает диагностика sink.
Подробности: [ошибки](ERRORS_AND_LIFETIME.md) и [форматы](OUTPUT.md).
